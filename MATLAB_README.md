# Gear Train Simulation (MATLAB)

Part of the `industrial-quality-inspection` project. This is the second stage of the pipeline:

```
Real gear photo  →  gear_inspector.py (Python)  →  gear_params.json  →  gear_train_sim.m (MATLAB)  →  animated simulation
     (image)          detects gears, counts teeth,      (measurements)      turns numbers into a
                       measures radii, finds meshing                        working kinematic model
                       pairs, outputs JSON
```

**Python's job:** turn a photo into numbers (tooth counts, radii, which gears mesh with which).
**MATLAB's job:** turn those numbers into a physical model you can animate and query — rotation speed, direction, and (as of this version) torque/force.

---

## Files

| File | What it is |
|---|---|
| `gear_train_sim.m` | The MATLAB function that loads `gear_params.json` and runs the simulation |
| `gear_params.json` | Generated by `gear_inspector.py` — NOT hand-written. Re-generate it any time you re-run the Python inspector. |

---

## Requirements

- MATLAB (Online or Desktop). No extra toolboxes needed — only base MATLAB (`jsondecode`, `containers.Map`, plotting).
- A `gear_params.json` file, produced by running the Python tool:
  ```bash
  python3 src/gear_inspector.py
  ```

---

## Usage

```matlab
gear_train_sim(jsonPath, imageName, refGearId, refDiameterMM, inputTorqueNm)
```

| Argument | Required? | Meaning |
|---|---|---|
| `jsonPath` | yes | Path to `gear_params.json` |
| `imageName` | yes | Which photo's gears to simulate — must match one of the names printed by `fieldnames(jsondecode(fileread(jsonPath)))` |
| `refGearId` | yes | The `id` of ONE gear in that image whose real size you know |
| `refDiameterMM` | yes | That gear's real outer (tip-to-tip) diameter, in mm — measured with calipers, or from a datasheet |
| `inputTorqueNm` | optional (default `1`) | Assumed torque, in Newton-metres, driving gear #1. **Not measured from the photo** — photos give geometry only, never load. Treat every torque/force number this prints as an ideal "what if" estimate. |

### Example

```matlab
% First, check which image names are available:
raw = jsondecode(fileread('gear_params.json'));
fieldnames(raw)

% Then run the simulation on one of them:
gear_train_sim('gear_params.json', 'imagesCopy_jpg', 1, 100, 2.5)
```

This prints:
1. The computed pixel-to-mm scale factor
2. A table of every gear's measurements in mm (position, tooth count, pitch/tip radius)
3. A table of each gear's rotation speed and direction (deg/s, sign = direction)
4. A table of each gear's ideal torque (Nm) and tangential force (N) at its pitch circle

...then opens an animated figure showing the gears spinning at their correct relative speeds and directions.

## What it computes, and how

**Rotation speed & direction:** For two external gears meshing, MATLAB's known laws of gearing say the angular velocity ratio is the exact inverse of the tooth-count ratio, and the two gears always spin in **opposite** directions:

```
omega_b = -omega_a * (teeth_a / teeth_b)
```

The script starts from gear id `1` at an arbitrary 60 deg/s, then walks every entry in `meshing_pairs` (from the JSON) to propagate speed and direction to every other connected gear.

**Torque & force:** Assuming a perfectly lossless (100% efficient, frictionless) gear train, mechanical power is conserved across every mesh — so torque and speed always trade off exactly inversely: a gear spinning faster always carries proportionally less torque.

```
torque_b = torque_a / (teeth_a / teeth_b)
force_N  = torque_Nm / (pitchRadius_mm / 1000)
```

Real gear trains always deliver **somewhat less** torque than this ideal number, due to bearing friction, tooth friction, and backlash. These numbers are an upper-bound estimate, not a measured spec.

## Assumptions & limitations

- **External spur gears only.** Meshing gears are assumed to always spin in opposite directions. Internal/ring gears aren't handled — `gear_inspector.py` doesn't detect those either.
- **Schematic teeth, not true involute profile.** The animation currently draws each tooth as a straight radial tick mark, not a real involute curve. Good enough to sanity-check tooth counts, rotation direction, and speed ratios — not accurate enough to check tooth-meshing clearance or manufacturing fit. (Real involute-profile rendering is a planned upgrade — see Roadmap below.)
- **Single input, single load path.** Gear id `1` (whichever sorts first) is treated as the input, driven at an arbitrary 60 deg/s and your chosen torque. A gear not connected to it through any meshing pair stays still and shows 0 torque/force (a warning is printed if this happens).
- **Torque/force are ideal estimates**, not measurements — see above.
- **Real-world scale depends entirely on your one reference measurement.** If `refDiameterMM` is wrong or a placeholder, every other number (positions, radii, force) scales proportionally wrong. Swap in a real caliper measurement whenever you have one.

## Troubleshooting

- **`Image "..." not found`** — the `imageName` argument must exactly match a name from `fieldnames(jsondecode(fileread('gear_params.json')))`. MATLAB sanitizes filenames (e.g. `images copy.jpg` becomes `imagesCopy_jpg`) — always check the field list first rather than guessing.
- **`No confirmed gears were found`** — that image had 0 gears detected in this JSON. Re-run `python3 src/gear_inspector.py` (optionally with `--neck-factor`) and re-export the JSON.
- **`refGearId not found`** — check the actual ids in that image with `raw.<imageName>.gears` in the MATLAB command window, and use one of those.
- Any other error: copy the exact red error text and the command you ran — that's what's needed to debug it.
